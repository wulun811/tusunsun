## 土行孙的主张：让 Agent 跟着工作变

先看要干什么活，再决定这次带哪些能力。这是土行孙的出发点。

场景把一类工作需要的组件组织起来，必需组件先启动，适合按需加载的能力留待调用；部分懒加载插件满足条件后可闲置回收。工作方式改变时，你可以选另一套场景、增减工具或替换适配器。同一个小内核承载这些不同搭配。

因此，**工作是出发点，场景是组织方式，懒加载与回收是运行机制，微内核支撑组合变化**。小内核和自包含安装服务于这个方向，不能单独证明它比其他 Agent 更好。

例如，纯文本问答可以使用 `chat`；需要读写项目文件时选择含文件工具的 `gateway` 或 `coding` 搭配；有自己的业务脚本时，再把它们做成工具并写进场景。场景由开发者选择和维护，具体清单用 `scene show <名称>` 查看。增加领域工具属于集成路径，不代表本包已经交付对应行业应用。

## 当前实现怎样承接这个方向

| 想解决的问题 | 当前机制 | 使用时须注意 |
|---|---|---|
| 不同工作需要不同的能力搭配 | JSON5 场景的 include、eager、plugins/lazy | 场景是组件配置；不承诺自动理解任意工作并生成正确装配 |
| 不必让所有能力都作为运行中插件常驻 | 能力索引、首次调用触发插件加载 | 服务、路由和监听器等必需组件要主动初始化；部分索引路径会导入模块，不是“启动时零导入” |
| 部分能力用完后可以释放 | 非 eager 懒加载插件的闲置回收、卸载与再次加载 | 回收受依赖、生命周期和闲置条件约束，不保证所有插件都可随时卸载或有固定节省比例 |
| 能看懂并改变这套机制 | 通用 Core、依赖解析器、插件管理与生命周期代码 | 替换适配器需要满足消费者契约，自定义组合仍需验证 |

当前开源包把这些机制用于本地对话与工具服务，通过 CLI、网页、HTTP/SSE 和 WebSocket 使用。“本地服务”说明当前交付形态，“按场景组装，按需加载，随工作调整”说明产品选择这个架构的原因。

## Pi 的比较对象要分层

| Pi 官方部分 | 已核对的职责 | 对选型的含义 |
|---|---|---|
| 交互式 Agent / coding-agent | 终端工作流、会话、模型与工具；可用 SDK 嵌入，也可用 RPC 进行进程集成 | 不能说 Pi 只能在终端使用，或不能做应用后端 |
| 扩展 API | 工具、命令、生命周期钩子、模型提供者、状态与界面扩展 | “可插拔、可扩展”是双方共有方向 |
| Chord | 跨进程对象/契约、状态同步与热重载机制 | 不能说 Pi 缺少底层运行时或组件生命周期 |
| Pi Durable | 持久对话与任务运行时；README 标注 Experimental | 与土行孙的会话文件不在同一保证层级；也不能把实验接口当稳定合同 |

依据：[Pi 仓库](https://github.com/earendil-works/pi)、[SDK](https://pi.dev/docs/latest/sdk)、[CLI 集成](https://pi.dev/docs/latest/cli-integration)、[扩展](https://pi.dev/docs/latest/extensions)、[Chord](https://github.com/earendil-works/pi/blob/main/packages/chord/README.md)、[Pi Durable](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)。这些是外部方的官方说明，不等于本项目对其实现完成了独立验收。main/latest 会变化，重新选型时需复核。

## 可成立的区别与不能成立的优越性

土行孙把按工作划分场景、区分必需/按需组件及管理生命周期放在直接定制面上，底层是通用的事件/命令/能力/服务接口。Pi 可以从交互式 Agent、SDK/扩展或更底层库进入。两者能力有重叠，差别主要在采用哪套接口、装配方式与分发边界；本轮没有证明 Pi 无法实现相同的工作方式。

土行孙当前明确的分发取舍是 Node ≥ 22（ADR-12；22 实测、24 声明未实测）、不从 npm 拉取运行依赖、把 `ws` 固定在包内并校验。它也承担手动跟踪上游安全更新的成本。未在同一运行环境比较 Pi 与土行孙的依赖闭包、完整代码量、内存、延迟或成功率，因此不做体积/性能排行榜，更不把“零 npm 依赖”写成“无第三方代码”。

对于已经使用 Pi 的人：若 Pi 的 SDK 和扩展已能满足需要，目前没有证据要求迁移。若你希望以场景维护多套工作搭配，直接调整这套小内核的加载/卸载机制，并接受维护和验证成本，可以试用土行孙。Pi 适配土行孙的模型或会话插件不是当前随包能力。

## 什么时候暂时不要选

- 只想得到一个无需自己装配的编码助手，且现有工具已经满足需要。
- 业务只是一次模型请求，没有会话、工具服务和组件组合的需求。
- 需要多人多租户隔离、恶意代码执行、分布式任务调度或崩溃后副作用一致性保证。
- 期待官方行业插件、完整观测平台或无需适配的所有模型支持。

这些边界应当跟随实现与验收证据更新，不能先在首页写成能力再等待代码补齐。
