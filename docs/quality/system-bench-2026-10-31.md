## 2. 口径

1. **启动 = spawn → HTTP 就绪端点返回 `<500`**。两边用同一个外部口径，不采信任何一方自报的日志时间戳。
2. **地板 = `node -e ""`**。没有地板就不知道 153 ms 里有多少是 Node 自己的进程创建。
3. **能力面不同必须写明**。土行孙量的是 `gateway` 场景；opencode 是完整产品（TUI、LSP、MCP、会话库、数据库初始化）。**这不是“谁更快”，是“装配了多少东西”。**
4. 上下文：把模型端点指向本地 recorder，抓一轮真实请求体；token 为统一尺度的估算（CJK 1.5 字符/token，其余 4 字符/token）。另做一次真模型校准（见 §5.1）。
5. 密度：同机同时拉起 N 个独立 `gateway` 进程，不含模型推理。

## 5. 每回合固定上下文

| 场景 | system prompt | 工具 schema | 请求体合计 | 估算 tokens |
|---|---:|---:|---:|---:|
| 土行孙 `gateway` | 676 字符 | 10 个 / 4,360 字符 | **5,164 字符** | **≈1,300** |
| opencode `run` | 9,604 字符 | 10 个 / 20,812 字符 | **30,740 字符** | **≈7,686** |

- 取的是**带工具的最大请求**：opencode 第一发是不带工具的辅助调用，拿第一个请求去比会得出相反的结论。
- token 是统一口径的**估算**，不是真 tokenizer；比的是同一把尺，不是绝对值。
- 差约 5.95×（字符）/ 5.9×（估算 token）。

### 5.1 真模型校准（一次性，非批量）

把两份请求体原样重放给 `deepseek-v4.1-flash` 一次，读响应的 `usage.prompt_tokens`：

| 场景 | 真实 prompt_tokens |
|---|---:|
| 土行孙 `gateway` | **1,548** |
| opencode `run` | **7,347** |

与 §5 的估算相比，误差分别在 16% 与 4% 以内；用真实值算，差距是 **7,347 / 1,548 = 4.75×**。估算给的是 5.9× —— 方向一致，幅度小一些；两个数都给，不挑好看的那个。
这次校准只花每侧一次输入，默认关闭，需显式加 `--allow-llm`；报告只写 token 数与比值，不写 key 或 header。

## 6. 密度（同机同时拉起 N 个独立 gateway）

| N | 起来 | 总 RSS | 每实例 | ready p50 | ready max | 失败 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 1/1 | 71.3 MB | 71.3 MB | 147.7 ms | 147.7 ms | 0 |
| 4 | 4/4 | 285.5 MB | 71.4 MB | 176.2 ms | 184.4 ms | 0 |
| 8 | 8/8 | 572.5 MB | 71.6 MB | 278.4 ms | 286.7 ms | 0 |
| 16 | 16/16 | 1149.1 MB | 71.8 MB | 529.4 ms | 639.6 ms | 0 |

**每实例常驻成本基本是平的**（71.3 → 71.8 MB，N=16 也不涨）；**就绪时间随争抢变差**（147.7 → 529.4 ms，12 线程跑 16 个）。

**没有做 opencode 侧的密度**：每个实例约 327 MB，N=16 就是 5.2 GB，且启动慢约 8 倍，这台机器会先于被测对象倒下。如实记 **NOT_MAPPED**，不折算成“我们赢”。

## 7. 能支持什么、不能支持什么

能说：

- 同一台机器上装配一个能接活的 gateway：土行孙 **153 ms / 71 MB**，opencode **1205 ms / 327 MB**。
- 每回合固定上下文：**5.2k 字符 vs 30.7k 字符**（真实 token 1,548 vs 7,347）。
- 16 个实例同机共存，总内存 1.15 GB，全部就绪。

不能说：

- **“快 8 倍”** —— 启动差 7.9×，但两边能力面不同，且开机时间不是用户感知的瓶颈。
- **“并行密度 8×”** —— opencode 侧没测，且密度取决于任务与模型并发，不取决于常驻内存。
- **“常驻低 70%”** —— 相对差是 78%，但那把“它多做的功能”也算进了账。

要写进 README 就写「本机实测 + 复跑命令」，不写倍数结论。

## 8. 三个容易产出假数的坑

1. **`.env` 会盖掉 `config.json`**。抓包实验必须用环境变量把端点钉死，并断言 recorder 真的收到请求；收不到就抛错，绝不把“没量到”写成“很小”。
2. **“第一个请求”不是“主回合”**。opencode 第一发不带工具，拿它去比会得到相反结论；现在取“带工具的最大请求”，并把请求个数写进 JSON。
3. **最小响应会触发重试风暴**。opencode 侧可能发出上千个请求；抓到目标就 `SIGKILL`，并给等待设上限。
