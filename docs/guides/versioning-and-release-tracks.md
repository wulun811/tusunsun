# 版本号与发布轨道

本文回答三个问题：**你手里的包属于哪一段历史**、**为什么版本号从 0.16 跳到 0.20**、
**以后怎么发版才不会把两段编号混在一起**。

## 1. 两段历史，不要拼成一条

土行孙的编号分成两段。它们的**含义不同**，不能当成同一条连续的公开历史来读。

| 段 | 范围 | 性质 | 有没有 git tag |
|---|---|---|---|
| 内部迭代轨道 | `0.1.0` → `0.16.0-rc.36` | 开发期的逐轮迭代，许多版本**从未对外发布**，其中相当一部分是内部审查轮次的快照（`rc.1`–`rc.36`） | **没有**（公开仓只给公开轨道打 tag） |
| 公开轨道 | `0.20.0` 起 | 面向外部使用者的发布；每个公开版**必有 tag** | 有，形如 `v0.20.0` |

**关键事实：`0.16.0-rc.36` 到 `0.20.0` 之间不是"跳过了 0.17–0.19 三个版本"，而是换了轨道。**
中间那几个号从来没有存在过，也不打算补。这个空档本身就是标记：**见到 0.17/0.18/0.19 的包，
一定是伪造或误标**。

## 2. 为什么首个公开版是 0.20.0 而不是 1.0.0

按语义化版本，`1.0.0` 承诺的是**公开 API 不再做破坏性变更**。以当前证据，这个承诺还兑不了：

- macOS / Windows 真实机器未实测（只有 Linux + Node 22.22.2 实跑全量）
- 浏览器侧安全 E2E、制品形态的真实模型链路未跑
- 若干并发边界（如 `forceOwner` 双并发接管）明确列为 NOT_RUN

所以公开轨道的第一个版本仍然是 `0.x` —— **`0.x` 在语义化版本里的本义就是"API 尚未稳定"**，
这是如实的表述，不是谦虚。真到 API 稳定那天再发 `1.0.0`，那时才谈得上兼容承诺。

**别把 `0.20.0` 里的 `0` 读成完成度**：它不是"做完了两成"，只表示"仍是 0.x 主版本"。
版本号不携带质量或完成度信息，去看 CHANGELOG 与验收证据。

## 3. 怎么判断你手里的包是哪一段

```bash
# 1) 看包内 package.json
node -p "require('tusunsun/package.json').version"

# 2) 看是否带 rc 后缀：带 -rc. 的一律是内部轨道，不是公开版
```

| 你看到的版本 | 判断 |
|---|---|
| `0.20.0` 及以后、无 `-rc` | 公开轨道 |
| 任意版本带 `-rc.N` | 内部迭代快照，**不建议**作为依赖基线 |
| `0.17.x` / `0.18.x` / `0.19.x` | 不存在，来源可疑 |

包里另有一处可交叉核对：模型适配器的 `User-Agent` 会写成 `tusunsun/<版本>`，
它与 `package.json` 的版本由随包门禁（`R0-113/Y10`）机械校验，两者不一致说明包被改过。

## 4. 发布检查单（维护者）

发布一个公开版，按顺序做完再打 tag：

1. 改 `package.json` 的 `version`（同时 `npm install --package-lock-only` 同步 `package-lock.json`）
2. 改 `plugins/model-openai.js` 的 `USER_AGENT` —— 漏了会被 `R0-113/Y10` 判红
3. 写 `CHANGELOG.md` 的 `## v<版本>` 段，且该段内必须出现实测数字（`→ NNNN` 或 `核心 ≤ NNNN 行`），
   否则 `scripts/sync-line-docs.mjs` 拒绝写入
4. `npm pack` 出制品 → `sha256sum` 记账到 `provenance/`
5. `node verification/run-formal.mjs` → **然后** `node scripts/measure-baseline.mjs`
   （顺序反了会留下过期报告，`baseline-check.mjs` 会判不一致）
6. `node scripts/release-gate.mjs` 双形态各跑一次，数字**分开记**
7. 打 tag：`git tag -a v<版本> -m "..."`，只给公开版打

### 两条不要做的事

- **不要复用内部轨道已经用过的号**。哪怕内容完全不同，`0.16.0` 这个名字在内部轨道上
  已经代表过别的东西，重号会让 CHANGELOG 无法指向。
- **不要给内部快照打 tag**。tag 是"这是公开版"的唯一信号，它一旦被稀释就失去意义。

## 5. 包名的历史包袱

`package.json` 的包名是 **`tusunsun`**；开发仓目录名是 **`tuxingsun`**，公开仓是 **`tusunsun`**。
包名与开发仓目录名不一致是既成事实：制品、`provenance/` 回执、`User-Agent`、README 标题全部写作 `tusunsun`，
改动会动摇已经验证过的制品身份，因此**保持 `tusunsun` 不动**。

（拼音上"土行孙"是 `tuxingsun`，`tusunsun` 少一个 `g`。这条如实记在这里，避免下一个人
把它当 bug 顺手"修"掉——那会让所有历史回执对不上。）
