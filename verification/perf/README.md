# 性能基线（rc.36，2026-10-30）

> 这个目录**不进 npm 制品**（`package.json.files` 不含 `verification/`），且 `tree_sha256`
> 计算时排除 `verification/`，所以记录性能数据不会让制品变成 STALE、不动固定点。

## 怎么跑

```bash
node verification/perf/bench.mjs      # 约 2 秒，输出 JSON
```

基准自带**前置断言**：每次都核对「调用次数 == handler 触发次数」且最后一次 `ok:true`，
不成立就抛错而不是报数。理由见下面第 3 节 —— 我在同一次会话里连错了三次，
每次量到的都是「拒绝路径」而不是「执行路径」，而拒绝路径看起来要快 50 倍。

## 1. 实测（Linux / Node v22.22.2，tmpfs，单线程）

| 路径 | p50 | p95 | 吞吐 |
| --- | --- | --- | --- |
| Core 能力直调（无 Cell 门） | **0.002 ms** | 0.003 ms | **约 42 万次/秒** |
| 受门保护派发，handler 近空（量门本身） | **0.245 ms** | 0.32 ms | **约 4000 次/秒** |
| 受门保护派发，handler 真读 4KB + sha256 | **0.354 ms** | 0.478 ms | **约 2600 次/秒** |
| 事件 `emit` | **0.001 ms** | 0.001 ms | **约 87 万次/秒** |
| Cell 全生命周期（create+accept+execute+close） | **3.5 ms** | 4.5 ms | — |
| `close()` 单条 | **0.68 ms** | 0.88 ms | — |
| `close()` 两条并发（rc.36 单飞） | **0.63 ms** | 0.73 ms | 比单条低约 0.05 ms（抖动级） |

三次连跑的 p50 分别是 0.245 / 0.250 / 0.250 ms，稳定。`close()` 单飞没有可测开销：
并发两条与单条的差在 ±0.1 ms 内摆动，符号都不固定。

### 结论

- **内核分发本身不是瓶颈**：微秒级。
- **门的开销约 0.25 ms**，是能力直调的 **100 倍以上**。花在票据校验、能力交集
  （Task ∩ Host ∩ Cell）、pre/dispatch 钩子、租约检查上。按 rc.35/rc.36 修的边界看，
  这个量级是合理代价，但它**确实是 250 微秒**，不能说成「几乎免费」。
- **真实工具调用受 IO 支配**：门 0.25 ms + 4KB 读盘 ≈ 0.35 ms，IO 只占三分之一。
- **限流是硬默认**：`30 次 / 60000 ms`，按（会话, 工具）分桶。单 Cell 连续调同一工具
  超过 30 次会被 `status:'blocked'` 拒。这是集成方很可能第一个撞上的墙，知道就好办。

## 2. 边界（不声称）

- 单线程、进程内、无并发竞争、无网络、无模型；文件全在 tmpfs。
- 只能**横向比较**（改前 vs 改后、这个版本 vs 下个版本），**不可当 SLA 或容量承诺**。
- 没有覆盖：真实模型往返、跨进程、Windows/macOS、长时间运行的内存与背压。
- 数字随机器与 Node 版本变动；换环境请重跑，不要引用本文件的绝对值。

## 3. 三次读错（写下来，免得下一个人重踩）

第一次报出 `executeOne` p50 = **0.005 ms / 14 万次每秒**。这个数字是假的，连错三次：

| 顺序 | 我看到的 | 真正原因 | 产品对错 |
| --- | --- | --- | --- |
| 1 | 1800 次全被拒 | 任务里没写 `required_capabilities`，`Task ∩ Host ∩ Cell = (none)` | 对：三集合交集 |
| 2 | 改成真派发后 handler 只跑了 1 次 | 只读能力有 **30s 结果缓存**；且工具参数被 schema 过滤，塞不存在的 `n` 打不散缓存键 | 对：设计如此 |
| 3 | 缓存绕过后变成 30 次就停 | 撞上执行器**默认限流 30 次/60 秒**，之后的 `0.005ms` 是限流器快速拒绝 | 对：产品限流 |

三次的共同点：**被拒绝的调用比被执行的调用快得多**，所以「量到了拒绝」永远表现为
「性能很好」。这也是为什么这个基准现在把断言写进代码：宁可抛错，也不报一个漂亮的假数。

另外还踩了两个「产品对我错」的门：`workspace_not_allowed`（`create` 需要 `trusted:true`）、
`task_scope_required` / `task_not_active`（Cell 身份不是任务票据，任务外派发一律拒）。
它们都不是缺陷，是已经过七轮复审的那几道边界在正常工作。
